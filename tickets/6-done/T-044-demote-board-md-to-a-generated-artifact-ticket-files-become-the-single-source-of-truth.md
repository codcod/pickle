# T-044 — demote BOARD.md to a generated artifact; ticket files become the single source of truth

## Description

**Design alternative to T-039 — accepted at refinement (2026-07-26).** T-039 hardened the
current BOARD.md design (escape-aware parsing, surgical sync, row-shape audit checks,
branch-cell repair); this ticket removes the design flaw those bugs grow from instead. On
acceptance, **T-039 was dropped as superseded** (its absorbed sources T-014/T-023/T-034/T-037
in `7-dropped/` remain the evidence record, now serving this ticket) and its one residue —
the move-atomicity item T-014·4 — was **folded into this ticket** (decision D7). Born from the 2026-07-26 chat analysis of T-039's bug class (alternatives considered:
SQLite as source of truth — rejected: binary blob in git kills diffable review, mergeability and
direct file authorship, which the flow explicitly permits; SQLite as derived cache — rejected:
fixes none of the writer-side bugs; git-bug / external trackers — rejected: abandons the
product's repo-native premise).

### The root cause this removes

Today the same facts are stored three to four times — a ticket's status lives in its directory
*and* its board section *and* its last History line; its grades live in frontmatter *and* board
cells; its branch lives in the plan *and* a board cell guessed from the filename slug. BOARD.md
is declared **hand-maintained**, yet three code paths write it (`board.MoveRow`/`AddTODORow`,
`sync`'s full rebuild, humans), none agreeing on the row model, and `strings.Split(line, "|")`
(`internal/board/board.go:282`) parses back what `renderRow` emits unescaped. Every confirmed
data-loss behaviour in the T-039 cluster is a consequence: sync deletes hand-written prose
(T-037), pipes and newlines malform rows that then audit clean (T-014·2, T-034), WIP counts and
the branch cell go stale or wrong because derived data is stored instead of computed (T-014·1,
T-023), and `audit` exists largely to detect drift between redundant copies of the same truth.

### The change

1. **Ticket files + status directories become the *only* source of truth.** Nothing about a
   ticket is stored anywhere else.
2. **BOARD.md becomes a pure generated artifact.** Regenerated wholesale from the ticket files
   by every `ticket new`, `ticket move` and `board sync`; it opens with a `<!-- generated by
   pickle — do not edit; run pickle board sync -->` banner. Because it is never parsed back,
   the render side needs only one-way cell sanitisation (replace `|`, collapse newlines) at a
   single choke point, and `insertIntoBoard`'s escape-unaware row parsing is **deleted**, not
   fixed — this settles T-039's central escape-vs-replace question by removing the parse side.
3. **Hand-written prose moves out of the board.** A `tickets/NOTES.md` (or equivalent) holds
   triage records, parked notes and cross-epic decisions; `pickle install` scaffolds it and the
   skill's board rule points prose there. Migration of this repo's existing board prose (the
   warning banner, triage notes, dependency-chain section) is part of the acceptance test.
4. **Ordering becomes data.** Hand-curated impact order within a child's TO DO/READY group
   cannot survive regeneration as row position, so it moves into the ticket (e.g. a `rank:` or
   ordering key in frontmatter, or deterministic grade-then-id ordering — refinement decides;
   this is the main open decision).
5. **Derived columns are computed or dropped.** WIP counts computed at render time (kills
   T-014·1); the `branch` column read from the ticket's plan/History or dropped (kills T-023).
6. **`audit` shrinks.** Board-consistency checks reduce to "the generated file matches a fresh
   render" (one byte-comparison), leaving audit focused on ticket-file invariants (T-040's
   scope, which this ticket does not absorb).

### Why this over T-039

T-039 is graded high/high/L and hardens three writers plus an auditor against each other. This
ticket deletes two of the writers' failure modes outright (no parse-back → no escape-aware
split; no preservation → no prose-deletion class) at an estimated M, and turns the remaining
bugs into non-problems by construction rather than by test coverage. The trade-offs accepted:
in-board prose annotations move to a sibling file, and hand row-ordering needs an explicit
representation.

### Confirmed design decisions (do not deviate without asking)

Approved by the user 2026-07-26 at refinement:

1. **D1 — ordering is deterministic**: within each child's TO DO/READY group, impact
   descending (existing `impactRank`, ranges included), tie-break id ascending — exactly
   `sync.sortRows`'s current behaviour. All other sections: id ascending. No `rank:`
   frontmatter; hand-curated order within the same grade is deliberately given up.
2. **D2 — the `branch` column is dropped** from IN DEVELOPMENT / IN REVIEW / REWORK. The
   real branch lives in the ticket's plan and History. Kills the T-023 class.
3. **D3 — terminal cells are derived from History, never carried over**: DONE `merged` =
   `yes — <text of the merge History line>` when `ticket.HasMergeLine` matches (extract the
   line), else `no — publish-gated`; DROPPED `reason` and REWORK `open findings` = the reason
   clause of the last transition line (written by `move --reason`, already newline-sanitised).
   `board.ParseCells` and its helpers are deleted.
4. **D4 — no terminal-row aging**: every DONE/DROPPED ticket is always rendered. Remove the
   "may age off the board" concept from code comments and docs.
5. **D5 — prose lives in `tickets/NOTES.md`**: scaffolded by `pickle install`; the board
   itself contains zero hand-written content and opens with a generated-file banner comment.
6. **D6 — audit board check = staleness check**: render fresh, byte-compare against the file
   after normalising the `Last updated:` line on both sides; on mismatch, one error:
   `BOARD.md is stale or hand-edited — run pickle board sync`. The per-row board cross-checks
   are deleted.
7. **D7 — fold in T-014·4**: `move.Move` must not leave a ticket whose History records a
   transition it did not make. Write the updated text to the **new** path first, then remove
   the old file (never append-then-rename).
8. **D8 — T-039 dropped as superseded** (bookkeeping done at refinement, not on this branch).
9. **Cell sanitisation is one-way and total**: a single `sanitizeCell` choke point applied to
   every rendered cell — replace `|` with `¦` (U+00A6), collapse `\r`/`\n` to a single space,
   trim. Nothing ever parses cells back (settles T-039's escape-vs-replace by construction).
10. **The whole file is generated** — preamble and all. No preserved regions, no appendix. The
    generated preamble: banner comment, `# Board`, one short pointer paragraph (board is
    generated; edit tickets, not the board; prose → `tickets/NOTES.md`), per-child WIP-limit
    line, `Last updated: <date>`.

### Tasks

#### Task 1 — the single renderer (`internal/board`)

Replace the write-side of `internal/board/board.go` with one pure function:

- `Render(tickets []*ticket.Ticket, cfg *config.Config, date string) string` — produces the
  entire BOARD.md: banner + preamble (decision 10), then the seven sections in `sync.boardOrder`
  order, each child sub-grouped (`### <child> (n/limit)` with WIP counts computed at render
  time for IN DEVELOPMENT / IN REVIEW), rows per decisions 1–4, all cells through
  `sanitizeCell` (decision 9).
- Move `sortRows`, `impactRank`, `boardOrder` here from `internal/sync`.
- New column sets: IN DEVELOPMENT / IN REVIEW / REWORK lose `branch` (decision 2) — update
  `SectionColumns`; REWORK's columns become `id | title | open findings`.
- Add to `internal/ticket/ticket.go`: `MergeLine(text) string` (the matched merge History
  line's text, reusing the `HasMergeLine` regex at `:217`) and `LastHistoryReason(text) string`
  (the `: <reason>` clause of the last transition line, reusing `historyRE` at `:105`; "" if
  none) — for decision 3.
- **Delete**: `AddTODORow`, `MoveRow`, `insertIntoBoard`, `removeRowByID`, `sectionSpan`,
  `subgroupSpan`, `insertLines`, `ParseCells`, `splitCells`, `zipCells`, `write`. **Keep**
  `Parse` (read-only) solely for `sync`'s informational drift summary.
- Rewrite `internal/board/board_test.go` as renderer tests: golden full-file render for a
  fixture tree; pipe + CR/LF in title renders sanitised; WIP counts computed; merged/reason
  cells derived from History; deterministic ordering incl. grade ties; `Render` is a pure
  function of its inputs (same inputs ⇒ byte-identical output).

#### Task 2 — sync becomes regenerate (`internal/sync/sync.go`)

`Sync(root, cfg, dryRun)` becomes: `ticket.LoadAll` → refuse on load issues (unchanged) →
`board.Render` → compare with the existing file (normalising `Last updated:`) → write when
changed. Keep the row-membership drift summary (old `board.Parse` rows vs rendered membership)
and the audit self-check after write. Delete `splitBoard`, `matchStatus`, `refreshLastUpdated`,
`renderRegion`, `rowFor`, `onlyListed`, the carry-over plumbing, and `defaultHeading`. Update
`internal/sync/sync_test.go`: the T-037 reproduction flips — hand-written prose inside the
board is **replaced** by regeneration (that is now the contract) while `tickets/NOTES.md` is
never touched; sync is idempotent (second run: `Changed == false`); `--dry-run` never writes.

#### Task 3 — rewire the writers (`internal/cli/ticket.go`, `internal/move/move.go`)

- `internal/cli/ticket.go:133`: replace `board.AddTODORow` with regenerate-and-write (share
  one small helper with sync, e.g. `sync.Regenerate(root, cfg)`).
- `internal/move/move.go`: replace the `board.MoveRow` call + `rowData` with the same
  regenerate call, after the file move. Drop `renderDepends` if unused.
- `move_test.go`: moves regenerate the whole board (assert a move refreshes WIP counts — the
  T-014·1 regression); a `--reason` shows up in the DROPPED/REWORK cell via History derivation.

#### Task 4 — move atomicity (T-014·4, decision 7)

In `move.Move`, replace append-History-to-old-path + `os.Rename` with: build the new text,
write it to the **new** path (`os.WriteFile`), then `os.Remove` the old path. A crash between
the two leaves a duplicate id — which `audit` already reports (`duplicate id`) and is
recoverable by deleting the stale copy; it can no longer leave a ticket recording a transition
it did not make. Add a `move_test.go` case asserting the old path is gone and the new path
carries the History line.

#### Task 5 — audit staleness check (`internal/audit/audit.go`)

staleness check. Keep every ticket-file invariant (frontmatter keys, grades, project, deps,
