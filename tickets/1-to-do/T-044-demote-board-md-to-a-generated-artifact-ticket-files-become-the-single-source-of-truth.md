# T-044 — demote BOARD.md to a generated artifact; ticket files become the single source of truth

## Description

**Design alternative to T-039 — refine one, not both.** T-039 hardens the current BOARD.md
design (escape-aware parsing, surgical sync, row-shape audit checks, branch-cell repair). This
ticket proposes removing the design flaw those bugs grow from instead. If this ticket is
accepted at refinement, T-039 shrinks to whatever residue remains (likely only the move-atomicity
item, T-014·4) or is dropped as superseded; if this ticket is rejected, drop it and refine T-039
as scoped. Born from the 2026-07-26 chat analysis of T-039's bug class (alternatives considered:
SQLite as source of truth — rejected: binary blob in git kills diffable review, mergeability and
direct file authorship, which the flow explicitly permits; SQLite as derived cache — rejected:
fixes none of the writer-side bugs; git-bug / external trackers — rejected: abandons the
product's repo-native premise).

### The root cause this removes

Today the same facts are stored three to four times — a ticket's status lives in its directory
*and* its board section *and* its last History line; its grades live in frontmatter *and* board
cells; its branch lives in the plan *and* a board cell guessed from the filename slug. BOARD.md
is declared **hand-maintained**, yet three code paths write it (`board.MoveRow`/`AddTODORow`,
`sync`'s full rebuild, humans), none agreeing on the row model, and `strings.Split(line, "|")`
(`internal/board/board.go:282`) parses back what `renderRow` emits unescaped. Every confirmed
data-loss behaviour in the T-039 cluster is a consequence: sync deletes hand-written prose
(T-037), pipes and newlines malform rows that then audit clean (T-014·2, T-034), WIP counts and
the branch cell go stale or wrong because derived data is stored instead of computed (T-014·1,
T-023), and `audit` exists largely to detect drift between redundant copies of the same truth.

### The change

1. **Ticket files + status directories become the *only* source of truth.** Nothing about a
   ticket is stored anywhere else.
2. **BOARD.md becomes a pure generated artifact.** Regenerated wholesale from the ticket files
   by every `ticket new`, `ticket move` and `board sync`; it opens with a `<!-- generated by
   pickle — do not edit; run pickle board sync -->` banner. Because it is never parsed back,
   the render side needs only one-way cell sanitisation (replace `|`, collapse newlines) at a
   single choke point, and `insertIntoBoard`'s escape-unaware row parsing is **deleted**, not
   fixed — this settles T-039's central escape-vs-replace question by removing the parse side.
3. **Hand-written prose moves out of the board.** A `tickets/NOTES.md` (or equivalent) holds
   triage records, parked notes and cross-epic decisions; `pickle install` scaffolds it and the
   skill's board rule points prose there. Migration of this repo's existing board prose (the
   warning banner, triage notes, dependency-chain section) is part of the acceptance test.
4. **Ordering becomes data.** Hand-curated impact order within a child's TO DO/READY group
   cannot survive regeneration as row position, so it moves into the ticket (e.g. a `rank:` or
   ordering key in frontmatter, or deterministic grade-then-id ordering — refinement decides;
   this is the main open decision).
5. **Derived columns are computed or dropped.** WIP counts computed at render time (kills
   T-014·1); the `branch` column read from the ticket's plan/History or dropped (kills T-023).
6. **`audit` shrinks.** Board-consistency checks reduce to "the generated file matches a fresh
   render" (one byte-comparison), leaving audit focused on ticket-file invariants (T-040's
   scope, which this ticket does not absorb).

### Why this over T-039

T-039 is graded high/high/L and hardens three writers plus an auditor against each other. This
ticket deletes two of the writers' failure modes outright (no parse-back → no escape-aware
split; no preservation → no prose-deletion class) at an estimated M, and turns the remaining
bugs into non-problems by construction rather than by test coverage. The trade-offs accepted:
in-board prose annotations move to a sibling file, and hand row-ordering needs an explicit
representation.
