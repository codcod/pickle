[#installation]
= Installation

[NOTE]
====
*Two different "installs."* This page installs the *`pickle` binary* on your
machine. The `pickle install` _command_ (see <<cmd-install>>) is a separate
step you run *inside a project* to lay down the flow (skill, board, markers).
====

== Homebrew

Via the tap:

[source,sh]
----
brew install codcod/taps/pickle
----

== go install

Go 1.26+, any platform:

[source,sh]
----
go install github.com/codcod/pickle@latest
----

NOTE: `brew install` / `go install` work once the GitHub repo + tap exist and a
release tag is cut — see `RELEASING.md` in the repository.

== From source

Requires Go 1.26+ and (optionally) https://github.com/casey/just[`just`].
Releasing also needs https://goreleaser.com[`goreleaser`]
(`brew install goreleaser`).

[source,sh]
----
git clone https://github.com/codcod/pickle
cd pickle
just build         # → ./pickle   (or: go build -o pickle .)
just test          # go test ./...
just lint          # go vet + gofmt check
just dist-check    # validate .goreleaser.yaml
just dist-snapshot # local cross-compiled build into ./dist (no publish)
./pickle version
----

Cutting an actual release is tag-driven and documented in the repository's
`RELEASING.md`.

== Then, inside any project

[source,sh]
----
pickle install        # lay down brine — see the CLI reference
pickle hooks install  # optional: guard ticket bookkeeping (once per clone)
pickle version
----

`pickle hooks install` arms two guards. A `pre-commit` guard refuses ticket
and board bookkeeping staged on a feature branch, and a `pre-push` guard
refuses a push whose destination is such a branch when the range against the
remote base still carries the same bookkeeping. Together they enforce the one flow rule nothing
else can: at both commit time and publish time. Hooks live in `.git/` and are
never cloned or pushed, so run this
once in **each** clone you work from, including a fresh clone of a project
that already uses it. See <<cmd-hooks>>.

Both guards run whatever `pickle` is first on your `PATH`, not necessarily the
binary that just ran `hooks install` — if you installed from a freshly built
binary while `PATH` still resolves an older release (Homebrew lag, a second
clone, `go install` alongside a packaged copy), `pickle doctor` will tell you
the guards are inert instead of reporting them as healthy
(<<hooks-version-skew,version skew>>).
