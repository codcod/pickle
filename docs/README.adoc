  link:user-manual/concepts/lifecycle.adoc[lifecycle],

each project (`{skill-dir}/resources/tickets-README.md`) — the manual explains
and summarises them; where the two disagree, the skill wins.

== Validating

`just docs-check` runs two checks. First, a render pass that fails on any
warning, such as broken includes. Second, a Go test that catches issues the
render pass misses silently — a dead `<<anchor>>` cross-reference, an
inter-document `xref:<file>.adoc` form (dead once split into PDF/EPUB
chapters), or a page under `docs/user-manual/` that nothing `include::`s:

[source,sh]
----
just docs-check    # snowball check (render-and-discard) + go test . -run '^TestDocs'
----

== Building

The manual renders to PDF and EPUB with
https://github.com/codcod/snowball[snowball] (configured by `snowball.yaml` at
the repo root). One-time toolchain setup:

[source,sh]
----
brew install codcod/taps/snowball   # the snowball binary
snowball setup                      # installs its pinned asciidoctor gems
snowball doctor                     # verify: "toolchain ok"
----

Then:

[source,sh]
----
just docs-build    # snowball build -o dist/docs
----

renders `dist/docs/pickle-user-manual.pdf` and
`dist/docs/pickle-user-manual.epub`, stamped with `git describe` as the
revision. Artifacts are never committed — `dist/` is gitignored and
`just clean` removes it.
